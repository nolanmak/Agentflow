# AF-19: Migrate application, CLI, browser, and tests from JavaScript to TypeScript

## Outcome

Ship TypeScript source with checked boundaries for native agents, speech providers, settings, jobs, HTTP, WebSockets, and browser state. Preserve existing runtime behavior and installed CLI/service integration. This is a migration issue, not part of the Deepgram picker change.

## Acceptance criteria

- [x] Handwritten application modules under src/ and public/, executable scripts under scripts/, tests, and Playwright configuration use .ts source. JavaScript is generated build output only, with any unavoidable tooling exception individually documented.
- [x] npm run typecheck passes with strict: true and noEmit: true. No @ts-nocheck, blanket @ts-ignore, or migration-wide disabling of strictness. Unknown external data is validated/narrowed; explicit any exceptions are isolated and explained.
- [x] Define typed contracts for agent/session IDs, job/event status unions, settings, speech requests/results, API payloads, and authenticated WebSocket messages. Invalid status transitions/payload shapes are rejected by negative type fixtures using @ts-expect-error plus runtime boundary tests where needed.
- [x] A clean npm ci followed by npm run build produces a runnable service, CLI/MCP entrypoint, and browser assets without requiring TypeScript tooling at runtime. Package bin, static imports, source maps, and copied HTML/CSS resolve from the build directory.
- [x] Existing native session IDs, exact user text, permissions, provider settings, and Keychain credentials are preserved. The migration creates no native inference/session calls during startup or build.
- [x] Installer/launchd and both MCP configurations target the compiled entrypoints. Updating paths preserves unrelated configuration and does not silently kill active native sessions. Document the migration from existing JavaScript entrypoints.
- [x] All existing unit/contract/HTTP/WebSocket/CLI/browser tests pass against the compiled implementation. Run a disposable live Deepgram speech check and native Codex same-session smoke; record Claude quota limitations without claiming a pass.
- [ ] CI runs clean install, typecheck, build, unit/integration tests, and browser checks on a documented Node version. Generated files, credentials, local recordings, and personal paths are excluded from Git.
- [x] README development/install/test commands match the compiled layout and have been executed from a clean checkout.

## Test-driven sequence

1. Add a failing clean-build/compiled-entrypoint smoke test before changing production imports or paths; record the red result.
2. Add minimal typed boundary contracts and negative type fixtures before migrating their consumers. Convert one subsystem at a time, preserving runtime assertions.
3. Start with settings/speech, then jobs/native adapters, HTTP/WebSockets, CLI/service, and browser. Validate external JSON as unknown rather than declaring it trusted with casts.
4. Run focused behavioral tests and tsc for each subsystem; refactor only after green. Do not replace existing tests with type checks or assert implementation internals solely to raise coverage.
5. Test package bin, static asset serving, MCP stdio, and launchd absolute paths from built artifacts. Do not require an active personal session for fixtures.
6. Run the complete suite and opt-in disposable live checks. Record command output and an acceptance-to-evidence mapping before closing.

## Scope

No framework rewrite, new UI, provider expansion, or agent behavior changes. Dependencies remain pinned. Generated JavaScript is expected at runtime; handwritten source should be TypeScript.
