# AF-17: Simple terminal speech through Agentflow CLI and one agent tool

## Outcome

In an existing Claude Code or Codex terminal, the user asks “Use Agentflow to read your answer aloud.” That same agent calls `speak({text})`, and Agentflow plays the supplied text through the Mac's configured TTS provider. The user keeps using their existing terminal dictation for input.

No skill, dashboard, browser, new chat, session attachment, or second inference model is required. A skill would only add optional instructions; it is not an execution dependency.

## Scope decision

This replaces the earlier broad T01–T14 terminal-voice proposal in this issue at the user's request to minimize complexity. The required path is:

`existing terminal agent → MCP speak(text) → Agentflow local speech service → Mac audio`

`agentflow speak --text ...` and stdin speech use the same service as the tool. Native agent context stays entirely in its existing process. The tool accepts text, not a reconstructed conversation or session-resume request.

## Current implementation

- CLI `agentflow speak --text "Hello"` and stdin speech exist.
- MCP `speak` exists and is registered for both native CLIs on the original Mac.
- Deepgram speech has been exercised with the local key and played through macOS audio.
- New MCP registrations may require the native client's tool refresh; active sessions must not be closed automatically. The CLI is available through each agent's ordinary shell tool when MCP has not refreshed.
- Both CLI and MCP use `/api/speak`; provider keys stay server-side/Keychain.
