# AF-09: Add the Deepgram transcription and speech provider adapter

## Outcome

Use Deepgram for speech recognition and/or generated speech, independently of the agent and the other speech provider.

## Dependencies

AF-07

## Milestone

M2: Speech providers

## Acceptance criteria

- [ ] STT calls the documented Listen API with valid audio content type and selected model/language, normalizing the transcript response.
- [ ] TTS calls the documented Speak API with selected voice/model and output format and returns correctly labeled playable audio.
- [ ] API keys use server-side Token auth; capability validation prevents unsupported model/encoding combinations.
- [ ] Handle empty transcript, malformed channel/results structure, unauthorized, rate limit, timeout, cancellation, and truncated audio through the shared error contract.
- [ ] Pass shared provider tests and expose deliberate live connection/audio tests with honest verified/unverified results.

## Test-first implementation

1. Write failing actual request/response contract tests with fake Listen/Speak endpoints.
2. Test nested transcript extraction, content types, cancellation, non-audio success payloads, and provider errors.
3. Run mixed-provider STT/TTS orchestrator tests; optional streaming capability must have its own ordering/reconnect tests before advertised.

## Completion evidence

- [ ] Record the initial failing test and why it failed.
- [ ] Record focused passing tests and relevant integration/browser checks.
- [ ] Refactor while green and run affected regression suites.
- [ ] Map every acceptance criterion to a test or explicit manual evidence.
- [ ] Update documentation and identify any unverified live behavior.
